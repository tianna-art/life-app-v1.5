# デモデータ

`crincran_demo_data_to_share.xlsx` の内容です。480件の記録（2024-09-01 〜 2026-08-28）と、
その記録が残された「方向性」（領域5つ・なりたい姿17枚）。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `setup.tsv` | 初期設定シート。方向性となりたい姿。**手で編集する側** |
| `logs.tsv` | Daily Logs シート。480件。**手で編集する側** |
| `demo_data.sql` | 上の2つから生成。編集しない |
| `demo_data_remove.sql` | 同上。入れたものを取り消す |

TSV を直したら `node scripts/build-demo-sql.mjs` で SQL を作り直します。
ラベルはアプリ側の定数（`src/constants/`）と照合されるので、
アプリが知らないカテゴリやタグがあればそこで止まります。

## 入れかた（ブラウザだけ）

1. GitHub の **Actions** → **Load demo data** → **Run workflow**
2. `email` に、入れたいアカウントのログイン用メールアドレス
3. `action` は `load`
4. `confirm` に `YES`
5. 実行

取り消すときは同じ手順で `action` を `remove` にします。

## 入るもの・入らないもの

**入るもの**: 記録480件と、方向性（領域・なりたい姿）。

**入らないもの**: AI の読み取り、progression、gain、月・年のまとめ。
これらはアプリが記録から見つけ出すものなので、ここで書いてしまうと
デモで確かめたいことそのものが偽物になります。

つまり読み込んだ直後は、LIST には480件が並びますが、MAP は空のままです。
分析は記録を保存したときに走るので、既存の記録には走っていません。

## 気づいた点

- 初期設定の方向性は5つ選択されています。アプリの選択画面は4つまで（`MAX_AREAS`）ですが、
  DB 側に制限はないので5つとも入ります。
- なりたい姿の「力が出る環境が分かる」は、アプリ側では「力が出る条件が分かる」という
  ラベルになっています。同じカードなので id で対応させています
  （`scripts/build-demo-sql.mjs` の `LABEL_ALIASES`）。
- 自由記述が480件すべてにあります。実際のアプリでは §14 のとおり任意なので、
  記述のない記録の方が多くなるはずです。
